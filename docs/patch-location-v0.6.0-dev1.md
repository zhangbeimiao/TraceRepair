# Agent 0.6.0-dev1：符号锚点补丁定位

## 目标

Agent `0.5.0` 在 `historical-python-v1.0.0` 的锁定任务中产生了语义方向合理、但
hunk 行号偏移 87 行的候选 Diff。旧控制器只允许在声明位置前后 80 行内做精确匹配，
因此以 `PATCH_CONTEXT_MISMATCH` 安全拒绝。该结果保持为 `0.5.0` 的真实 `2/3`
pass@1，不修改、不重跑。

`0.6.0-dev1` 增加第二条定位路径，但不扩大模糊匹配权限：

1. 首先尝试 Diff 声明行的逐行精确匹配。
2. 然后在 ±80 行内寻找唯一的逐行精确匹配。
3. 若仍未命中，才在全文件寻找旧代码块；匹配必须全局唯一。
4. 候选 hunk 至少包含一行删除和两行未改动上下文。
5. 旧代码块必须完整位于 Python AST 的一个命名函数、异步函数或类中。
6. 任意条件不满足都拒绝写入；不使用编辑距离、模糊文本匹配或自动 rebase。

## 可观测性

每个成功应用的 hunk 都在工具 trace 中记录：

- Diff 声明行；
- 实际应用行；
- 定位模式：`advertised`、`bounded_exact` 或 `symbol_exact`；
- `symbol_exact` 对应的函数或类名。

记录中不保存源码正文或完整 Diff。

## 评测纪律

- `historical-python-v1.0.0`、Agent `0.5.0` 和终端哈希永久保留。
- More Itertools 只能作为已公开的开发分析材料，不能再称为未见锁定样本。
- `0.6.0-dev1` 完成开发测试后，需要创建新的 benchmark ID。
- 新锁定集必须来自此前未用于 Prompt、策略或测试调试的仓库。
- 新旧版本同时报告 pass@1、人工接管率、错误接受补丁数、Token 和时延。
