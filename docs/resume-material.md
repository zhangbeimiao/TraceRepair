# TraceRepair 简历与面试材料

## 简历项目名

**TraceRepair｜受控代码修复 Agent｜Python / SQLite / pytest / LLM Tool Calling**

## 推荐简历表述

- 设计“推理权—执行权”分离的代码修复 Agent：LLM 仅输出结构化只读工具选择与候选 Unified Diff，确定性控制器负责阶段白名单、Token/轮次预算、补丁策略和状态机调度。
- 实现补丁与执行安全门禁：路径白名单、改动规模限制、hunk 上下文唯一匹配、预登记 pytest 目标测试和完整回归；模型无任意 Shell、原仓库写入或自动合并权限。
- 基于 SQLite 持久化模型决策、工具事件、状态迁移与 Checkpoint，并用 SHA-256 校验恢复工件和工作区，实现进程重启后跳过已完成步骤的幂等恢复。
- 构建带 oracle 预检、不可覆盖 pass@1 记录和 SHA-256 哈希链的多仓库历史 Bug 评测；冻结 Agent `0.6.0` 在 5 个真实历史 Bug 上取得 **3/5 pass@1**，2 个失败候选被目标测试拦截并转人工，**错误接受补丁数为 0**，平均输出 273.8 Tokens。
- 将端到端状态机迁移到 LangGraph，同时保留 SQLite 单一持久化源；新增无执行权限的语义补丁复核节点，在相同 5 个已知开发任务上将 pass@1 从 **2/5 提升至 4/5**，错误接受补丁仍为 0，并量化平均 Token `315.6 → 543.2`、P50 时延 `9.985s → 14.329s` 的成本。

样本量只有 5 个，简历中不要写“准确率 60%”作为泛化结论。`3/5 pass@1` 加上开发/锁定划分和安全接管结果更诚实，也更容易解释评测协议。
同样不要把 `0.7.0-dev2` 写成“修复准确率 80%”：它是相同五个已知开发任务上的机制对比，尚未包含全新锁定仓库。

## 30 秒介绍

TraceRepair 是一个受控代码修复 Agent。模型负责根据 Issue 和源码观察选择搜索、读取并提出一次候选 Diff；控制器负责工具权限、补丁策略、目标测试、完整回归、Trace 和崩溃恢复。冻结的 Agent 0.6.0 在五个真实历史 Bug 上取得 3/5 pass@1，其中锁定集 1/2、每题只运行一次；两个失败候选都被目标测试拒绝，因此错误接受补丁数是 0。这个项目重点不是包装高成功率，而是让模型失败可见、可拒绝、可恢复。

## 两个可讲的 Debug 故事

More Itertools 任务中，模型生成的修改意图接近历史修复，但 Unified Diff 标注的 hunk 起点是 1098，唯一精确上下文实际位于 1185，相差 87 行。当前控制器只允许在标注位置前后 80 行内做精确、唯一的重定位，因此触发 `PATCH_CONTEXT_MISMATCH`。系统没有写源码、没有运行测试，直接进入 `needs_human`。

这个旧版失败推动了 `0.6.0` 的有界精确符号定位，但旧版 `2/3` 永久保留，不能回填。新版锁定评测中，youtube-dl 的候选补丁通过路径和 Diff 策略，却没有通过目标测试；控制器没有运行完整回归，也没有把它计为成功。这说明“安全拒绝”不仅发生在补丁应用前，测试门禁也能阻止语义错误进入审核。

LangGraph `0.7.0-dev2` 中，tqdm 候选新增 `__bool__` 并在 `len(self)` 抛出 `TypeError` 时返回 `True`；语义复核器将它原样保留。补丁策略允许它写入一次性工作区，但目标测试退出码为 1，所以回归测试没有启动，任务转入 `needs_human`。这个案例说明语义复核能提高修复率但不能取代可执行 oracle，也为后续受控测试反馈修复留下了具体问题。

## 不要这样写

- “代码修复准确率 100%”。
- “可自动修复任意 Python 仓库”。
- “锁定集失败是模型答案正确，只是系统太严格”。候选补丁未应用、未测试，不能算成功。
- “哈希链保证报告不可篡改”。准确说法是：在终端摘要已外部发布后，链式记录和校验和可检测后续篡改；它不等于第三方不可变存储。

## 面试时展示顺序

1. 先运行 `python scripts/showcase.py --section evidence`，展示稳定版 3/5、两次安全接管，以及 LangGraph 开发版 2/5 → 4/5 的收益、成本和“零 locked task”边界。
2. 再展示一条成功 Diff 及 policy、target、regression 三层门禁。
3. 展示目标测试失败被拦截，再补充旧版 `PATCH_CONTEXT_MISMATCH`，说明多层门禁分别处理定位与语义错误。
4. 最后展示补丁落盘后崩溃恢复，强调 SHA-256 校验和不重复模型调用。
