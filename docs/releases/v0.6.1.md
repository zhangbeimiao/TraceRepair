# TraceRepair v0.6.1

## Outcome

TraceRepair now has model-backed evidence beyond EventRelay without collapsing
different evaluation protocols into one inflated success rate. The public
configured repository measures repeat stability; a separate held-out trusted
repository measures a strict one-shot outcome.

## Frozen evidence

| Protocol | Runs | Successes | Average output tokens | Average tool calls |
|---|---:|---:|---:|---:|
| Public configured repository repeat stability | 5 | 5 | 179.6 | 5.0 |
| Held-out repository, one shot and no retry | 1 | 1 | 234.0 | 5.0 |

Every successful run passed the target test and the configured regression
suite before entering `awaiting_review`. The held-out run used three model
calls and was frozen whether it succeeded or failed.

## Evaluation integrity

- the held-out repository was committed before the provider request;
- an attempt marker was written before the request, so a crash could not enable a retry;
- prompt and policy changes after result reveal were forbidden;
- the public manifest omits repository source, name, commit, task configuration,
  and configuration hash;
- reproducibility identifiers remain only in ignored local audit data;
- the model still cannot run arbitrary shell commands or bypass target and regression tests.

## Scope

The `5/5` result measures stability on one public task. The `1/1` result is a
held-out one-shot demonstration, not a statistically meaningful generalisation
rate. Neither number claims reliable repair of arbitrary Python repositories.
