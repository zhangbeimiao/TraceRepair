# TraceRepair v0.5.0

TraceRepair v0.5.0 adds integrity-checked process recovery without changing the
frozen `0.4.0-dev1` evaluation cohort.

## Checkpoint recovery

- `--resume <task-id>` continues interrupted end-to-end runs.
- Fault injection is available immediately after `source_read` and
  `patch_applied` checkpoints.
- A diagnosed source slice is kept in the disposable workspace; SQLite stores
  only its relative artifact path, phase, and SHA-256 digests.
- A patch-stage restart verifies every modified file against the digest recorded
  by `apply_patch` before tests may begin.
- Successful search, read, model, and patch steps are not repeated. A restart
  after `patch_applied` performs zero additional model calls.
- Any missing, malformed, escaped, or tampered recovery artifact fails closed to
  `needs_human`.

## Demonstration

`scripts/checkpoint_recovery_demo.py` provides two zero-cost, two-session
scenarios backed by the same production workflow. The public site visualizes the
checkpoint, interruption, restart, integrity gate, skipped work, and final test
result from frozen sanitized traces.
